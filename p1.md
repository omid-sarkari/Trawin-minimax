10. CONCURRENCY
============================================================

The runtime must handle:

- double-click submit
- simultaneous submit requests
- autosave + submit race
- multiple browser tabs
- refresh during submission
- reconnect after network failure
- expired session + submit race

Operations must be idempotent where appropriate.

A submit request must not produce two evaluations.

Use PostgreSQL transactional guarantees / row locking / conditional
updates where necessary.

Do not rely on JavaScript-only locks.

Never create duplicate answer rows for the same session/question.

============================================================
12. ANSWER IMMUTABILITY
============================================================

NO new answer

must be accepted.

Enforce this server-side.

Do not rely on disabling buttons in the frontend.
